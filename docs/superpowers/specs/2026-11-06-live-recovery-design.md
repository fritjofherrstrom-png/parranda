# Recover Live without replacing the day

Fritjof asked to continue after the deployed Copenhagen check found an HTML502 on original Live completion and an unavailable overview despite a working independent Live dialog. Public Linje stays; no further design questions are required under the existing execution mandate.

The code retries rejected transport reads inside the capability lifetime, but treats a502 HTML response as terminal unavailable. Treat502/504 and an unreadable503 as interrupted completion reads on the existing cadence and token. A structured503 refusal,410, malformed200 and other errors remain terminal. Never retry a route upgrade on this basis, start another collection, extend the lifetime or recompose a route. The historical proxy/server cause remains unknown.

A completed independent lookup may refresh the overview as a read-only observation only when its request and reply both identify around_place, tonight and the displayed selected date, with the local3km query geometry. Bind that observation to the exact day object and intent generation. Pending, regional fallback, another scope/week/date, malformed envelopes and superseded requests cannot replace it. A stale held day cannot be relabelled as an answer to new controls. Retain health/counts, including partial or genuinely empty results. Query facts never modify the installed day, LAST/saved snapshots, publication authority, route or upgrade permission. The separate completion result remains authoritative for those contracts; a later old completion must not erase a successful explicit observation.

Alternatives considered by Codex: treating arbitrary errors as pending would hide definitive failures; copying dialog results into the composed response would conflate query scope/publication with original execution. Keep transport recovery and read-only display refresh separate. Week/other-scope results remain in the dialog, not the selected-day overview.
