# Sol: exact-head pedestrian-network acceptance

Run only after explicit QA/deployment authorization and a frozen PR head. This
is a handoff, not a claim that provider/Pi/browser acceptance occurred. Keep the
PR draft; do not merge or permanently enable routing or sources.

## Preconditions

- Verify exact PR head/CI; stop on drift. Read `CLAUDE.md`, the staging contract
  and `NETWORK_WALKING_SELECTION.md`.
- Establish an authorized Valhalla endpoint, pedestrian graph/build coverage
  and reuse/attribution terms. Do not assume public-demo permission. Without
  that prerequisite, live contribution is INCONCLUSIVE, not fixture acceptance.
- Snapshot staging images, Compose/env hashes, caches/state and resources
  without secrets. Use the exact immutable image on web and worker; routing
  configuration belongs to web. No new Pi host ports or unrelated services.
- Create a timestamped evidence directory; preserve all previous packages.

## Controlled cohort

Choose after head freeze: at least four unsupported places spanning three
countries/language regions. Include a river/bridge detour, railway/barrier
corridor, compact connected control and sparse small town. Kolding at most one
sentinel, never the main proof. No required winning identity. Use typed and
coordinate anchors, short and longer budgets, varied food/culture/fika/second
hand/green/views preferences and both desktop and mobile.

Pin exact anchor, date, language, preferences, budget and graph. Keep trusted
candidate inputs/source caches byte-identical for controlled comparisons:

1. Flag off on exact image: heuristic baseline.
2. Flag on, cold geometry cache: same inputs/sources.
3. Flag on, warm geometry cache: same normalized chain.
4. Flag off again: no routing consumption despite warm geometry.

Save public requests/responses, candidate IDs/families/eligibility, final stop
IDs, route shape, every leg's distance/minutes, total and target classification.
Changed supply is not selection causality. Distinguish a changed stop from
changed geometry only, and explain interest/preference/trust preservation.

## Negative and ownership cases

- Unreachable chain and unavailable provider: no heuristic network-success
  label; honest retry/retained prior day. A failed provider comparison is
  INCONCLUSIVE for selection quality, not a source/product FAIL.
- Trace actual `pedestrian` request, fixed endpoint, counts, response bytes,
  duration and concurrency. No names, preference text, tokens, redirect or URL
  drift. Do not infer network count from cache mtime.
- Warm identical geometry: zero routing requests. Source acquisition is a
  separate measurement; do not conflate the caches.
- Cancel during an outstanding routing body: DELETE/transport abort, no stale
  publication, body/socket closure after last owner leaves. Where practical,
  verify that an active second consumer preserves shared work.
- Pins and events preserve identities and measured impact. Their failed final
  caps withhold this new day; do not claim network pin shedding or event removal.
- Polyline, total and expanded leg cards agree. Coordinate markers do not move;
  typed search centre is not counted as a walking start. Inspect snapping gaps,
  ferries and implausible paths rather than assuming access is proved.
- Fixed OSM attribution/disclaimer on desktop/mobile; Keep/Not-this, loading,
  error/degraded states, console/network and no private option/payload leakage.
- Measure web/worker RSS, CPU/cgroups. No Pi graph import, native routing child
  or routing temp-disk growth is expected. Cache limits are per web process;
  remote graph-server resources are separate and must be identified.

## Revision and harness gates

The interrupted `0399d99` run is partial historical evidence, not acceptance for
any corrected head. Its Pi observer buffers the complete upstream body, has an
independent timeout and does not propagate downstream disconnect upstream.
Do not use that proxy to prove native provider body/socket cancellation or
unmodified streaming/resource limits. Preserve its logs; replace measurement
with passive observation or independently verified transparent instrumentation.

Before a rerun, isolate the QA target from public tunnels and unrelated traffic.
Verify that no other browser/agent owns the browser context. Pin source-cache
manifests only after background acquisition has quiesced; source changes during
an off/on pair invalidate selection causality. A matching response hash without
the corresponding raw response does not prove geometry or rendered output.

Add focused failure regressions before expensive provider QA:
- Initial provider 503/timeout/capacity failure must not select another identity
  as if the initial route had a measured detour. No new unmeasured day is shown.
- Distinguish temporary provider/capacity messages from generic geometry
  rejection and invalid operator setup; do not blame source quality.
- Cold failure and retained-day failure both use an explicit normal-lifecycle
  retry for retryable errors; rapid double activation yields one new request.
- A failed revision leaves the previous day visible and clearly old, not labeled
  as satisfying newly requested preferences. No automatic retry storm.
- Fractional minutes are human-formatted in every visible leg/detail view;
  underlying distances/minutes retain precision and target/cap checks.
- Routing health reports configuration only, never claims live graph readiness;
  invalid enabled configuration is diagnosed without exposing the endpoint.

Synthetic faults can prove these contract/UI paths, but never substitute for
live graph/barrier or provider transport acceptance. Clearly label fixture,
real-browser-with-fixtures, and live-provider evidence separately.
